# AI 图片检测

引用一张图片发送触发词（默认 `ai吗？`），检查图片的 AI 生成与来源信号，可再请多个视觉模型共同判断，并引用原图回复。对应插件：`ai_image_detector`。

自 **v3.2.0** 起提供。检测来源开关、视觉模型共同识别和自定义触发词在 v3.3.0 之后的版本提供：升级后原有 OpenAI 密钥继续生效，三项检测来源默认开启，触发词默认仍为 `ai吗？`、`ai吗?`、`ai吗`，无需重新配置。

在 OneBot V11 群聊或私聊中，**引用一条只包含一张图片的消息**，回复：

```text
ai吗？
```

触发词匹配不区分英文大小写，`AI吗`、`Ai吗？` 也会触发。与其他命令一样，可直接发送触发词、加命令前缀（如 `/ai吗？`）或 `@机器人` 后发送。群聊中引用消息后 @机器人，或直接回复机器人的消息时，消息以触发词开头或结尾也会触发（如「这张是ai吗？」）；没有引用消息时须完整发送触发词，`@机器人 你是ai吗` 这类提问不会触发。群或好友必须已允许处理入站消息。当前不支持官方 QQ Bot 的引用图片。

机器人回复会引用**原始图片消息**，让检测结果与对应图片关联。检测失败或繁忙提示同样引用原消息；若用户未引用任何消息，操作提示会引用用户发送的命令消息。

## 管理入口

侧栏 **AI 图片检测** 分为四页：

| 页面 | 路径 | 内容 |
| --- | --- | --- |
| 检测来源 | `/ai-image/sources` | 本地 C2PA、OpenAI C2PA、SynthID（OpenAI）开关、OpenAI API Key 与 OpenAI 检测使用的代理 |
| 视觉模型 | `/ai-image/vision` | 视觉模型总开关；添加、编辑、启停和删除 OpenAI / Anthropic 兼容的视觉模型，每个模型单独保存；获取模型列表、测试响应、查询余额 |
| 触发命令 | `/ai-image/command` | 修改触发词、恢复默认或关闭命令 |
| 检测缓存 | `/ai-image/cache` | 缓存开关与保留条数上限；查看检测过的图片（预览）、回复内容与 SHA-256，修改或删除保存的结果，或清空全部 |

保存后立即生效，无需重启。

### 触发命令

每行一个触发词，最多 20 个、每个不超过 32 个字符。关闭后机器人不再响应，已填写的触发词会保留。保存时与其他命令按当前前缀集合做冲突检查，冲突时拒绝保存。默认触发词可点「恢复默认」找回。

### 检测来源

| 来源 | 说明 | 是否上传图片 |
| --- | --- | --- |
| 本地 C2PA | 在机器人本机读取并校验图片内嵌的 C2PA 凭证，可识别不同厂商的标准 AI 生成 / 合成声明 | 否 |
| OpenAI C2PA | 识别 OpenAI 签发的 AI 生成凭证，并报告签名状态与签发者 | 是 |
| SynthID（OpenAI） | 识别 OpenAI 接口支持的 SynthID 水印 | 是 |

OpenAI 的 Content Provenance 接口每次请求同时返回 C2PA 与 SynthID 结果，不能只查询其中一项。因此只要两项中任一开启，就会把原图上传一次；只开一项时，另一项结果不显示也不参与结论；两项都关闭时不调用 OpenAI。关闭的来源不出现在回复中。所有来源都关闭，且视觉模型总开关关闭或没有启用的模型时，命令只提示管理员尚未启用检测方式，不会下载图片。

OpenAI 检测的数据流：

1. 在 **检测来源** 页填入 OpenAI API Key 并保存；留空保存保留原密钥，点击「清除检测密钥」才删除。
2. 用户触发后，机器人下载 QQ CDN 提供的图片原始字节，先做本地 C2PA 检查（若开启）。
3. 开启 OpenAI 项目并配置密钥后，同一图片上传 `https://api.openai.com/v1/content_provenance_checks`。

密钥通过现有 `WEB_SECRET_KEY` 加密存入数据库。设置接口只返回是否配置，不返回原值或预览。开启 OpenAI 项目但没有密钥时，回复会标注 OpenAI C2PA / SynthID 未完成检测。接口无权限、限流或失败时保留其他结果，不把失败写成“未检出”。

### 视觉模型共同识别

视觉模型根据画面内容给出参考判断，与来源检测并行运行。数量不设上限。

页面顶部的「启用视觉模型」是总开关（默认开启），切换后立即生效。关闭后检测时不调用任何视觉模型，回复中不出现视觉模型结果；各模型的配置和启停状态保留，仍可编辑、获取模型列表、测试响应和查询余额。重新开启后按各模型自己的启停状态调用。

列表默认收起，每个模型只显示一行摘要：名称、接口类型、模型、接口地址（官方地址显示为「官方地址」）和密钥是否配置。点击标题展开编辑：

- 每个模型**单独保存**：「保存此模型」只提交这一个模型，其他模型和它们未保存的修改不受影响；保存成功后自动收起。「放弃修改」恢复为已保存的内容。
- 标题栏的启用开关**立即生效**，不会连带保存正在编辑的其他字段。
- 有未保存修改时，标题旁显示「有未保存修改」，收起后仍会保留。
- 「删除」需要确认，已保存的 API Key 会一并删除。
- 「添加视觉模型」新增一张展开的卡片，填写后点「创建此模型」保存；「取消添加」直接丢弃。新建时标题栏开关决定创建后是否启用。

每个模型包含：

| 项 | 说明 |
| --- | --- |
| 名称 | 回复中显示的名称，不超过 32 个字符，不可重复 |
| 接口类型 | **OpenAI 兼容**：请求 `{接口地址}/chat/completions`；**Anthropic**：请求 `{接口地址}/v1/messages`，同时发送 `x-api-key` 与 `Authorization: Bearer`，兼容只认其中一种的网关 |
| 接口地址 | 可选。留空使用官方地址（`https://api.openai.com/v1`、`https://api.anthropic.com`）；可填写兼容同一格式的第三方服务或本地服务，与官方 SDK 的 base URL 写法一致 |
| 模型 | 模型名称，须支持图片输入 |
| API Key | 逐条加密保存、只写不读；留空保留原密钥。无需鉴权的本地服务可不填 |
| 启用 | 停用后保留配置但不调用 |
| 代理 | 选择 **系统 → 网络代理** 中的一个代理，或直接连接（仍遵循运行环境代理变量）；每个模型可以选不同的代理 |

修改已保存模型的接口类型或地址时，必须重新填写 API Key，避免已存但不可读回的密钥被发往新地址。地址只接受 `http://` 或 `https://`，不能包含账号、查询参数或空白字符；本地服务可用 `http://`，公网服务请使用 `https://`。

每个模型返回「倾向 AI 生成 / 倾向非 AI 生成 / 无法判断」、可选的置信度（模型按 0–1 小数作答时换算为百分比）和不超过 80 字的理由，回复按模型逐行列出并汇总多数意见：

- 有受信任的来源证据时，结论以来源证据为准，视觉模型意见不改变结论。
- 没有来源证据时，结论写明有几个模型倾向 AI 或倾向非 AI，并标注“仅供参考”；多数倾向非 AI **不能证明非 AI**。没有过半数的倾向时结论为无法判断，只有同时出现「倾向 AI」与「倾向非 AI」时才注明意见不一致。
- 单个模型失败、超时、拒答或返回格式无法解析时，只把该模型标为未完成，不影响其他结果；回复不包含上游错误详情。

每次检测会把图片发给**每个已启用**的模型：启用越多，费用越高、回复越长，等待时间取决于最慢的模型（单个最多 60 秒）。只保存不启用的模型不会产生请求。

启用视觉模型意味着图片会发送给对应供应商，费用以其计费为准。PNG / JPEG / WebP 小图原样发送；GIF、动图以及超过 2048 像素或约 3.5 MB 的图片，会转为不超过 2048 像素的首帧 JPEG（满足 Anthropic 单图 5 MB 限制）。提示词要求模型忽略图片中的文字指令；视觉模型不是可靠的 AI 图片鉴别器，可能误判。

### 获取模型、测试响应与查询余额

视觉模型页的每个模型卡片提供三个操作。它们使用卡片上**当前填写**的内容（包括尚未保存的修改），未重新填写密钥时沿用已保存的密钥，并经该模型所选的代理连接。修改了接口类型或地址但没有重新填写密钥时，三个操作都会被拒绝，规则与保存相同。

- **获取模型列表**：OpenAI 兼容接口请求 `{接口地址}/models`，Anthropic 请求 `{接口地址}/v1/models`（自动翻页）。接口声明了图片输入能力时（如 DeepSeek 的 `input_modalities`、Anthropic 的 `capabilities.image_input`、OpenRouter 的 `architecture.input_modalities`），列表会标注「支持图片」/「不支持图片」，支持图片的排在前面；OpenAI 等未声明的接口不作标注。选择后填入「模型」，仍需保存才生效。
- **测试响应**：用机器人生成的一张 256×256 测试图走一遍真实检测请求，不上传任何用户图片。成功时显示耗时、对测试图的判断，以及接口返回的 token 用量；失败时显示原因和上游返回的错误说明（仅 Web Admin 可见，群聊回复不包含）。测试是一次正常调用，会按供应商计费。
- **查询余额**：仅在接口地址指向下列官方主机时显示，使用同一个 API Key 查询：

| 供应商 | 识别的主机 | 查询接口 | 显示内容 |
| --- | --- | --- | --- |
| DeepSeek | `api.deepseek.com`（OpenAI 与 Anthropic 兼容地址均可） | `GET https://api.deepseek.com/user/balance` | 各币种总余额、赠送余额、充值余额，以及是否可继续调用 |
| Kimi（月之暗面） | `api.moonshot.cn`（人民币）、`api.moonshot.ai`（美元） | `GET https://{主机}/v1/users/me/balance` | 可用余额、代金券余额、现金余额；可用余额不大于 0 时提示无法调用 |

余额查询始终通过 HTTPS 发往上述官方主机。OpenAI、Anthropic 没有可用普通 API Key 查询余额的接口；OpenRouter 的额度接口需要单独的管理密钥，暂不支持。

### 检测缓存

开启检测缓存时（默认开启），每次检测完成后，回复内容会按图片原始文件的 **SHA-256** 保存到数据库。之后有人再引用同一张图片询问时，机器人直接回复保存的结果，并在末尾注明「同一图片此前已检测过」，不再调用 OpenAI 或视觉模型，也不重新做本地 C2PA 检查，避免重复计费和等待。图片仍会下载一次用于计算哈希；QQ 重新压缩或转存过的图片字节不同，会被当作新图片检测。

- **只保存完整结果**：OpenAI 检测失败，或任一视觉模型失败、超时、拒答时不保存，下次询问重新检测。没有配置 OpenAI 密钥等配置性的「未完成」会照常保存，因为配置变化后会自动重新检测（见下一条）。
- **配置变化后自动重新检测**：保存时会记录当时的检测配置（三项来源开关、是否配置 OpenAI 密钥、实际调用的视觉模型（总开关关闭时视为没有）及其名称、接口类型、接口地址和模型，以及回复格式版本）。这些配置变化后，未修改的结果在下次询问时重新检测并覆盖，**检测缓存** 页会把它们标为「配置已变更」。只更换密钥或代理不算配置变化。
- **管理员修改**：在 **检测缓存** 页展开一条记录即可修改回复内容。修改过的结果始终沿用，不因配置变化而重新检测，也不会被自动清理；回复末尾注明「管理员复核后的结果」。删除一条记录后，下次询问会重新检测。
- **保存的内容**：SHA-256、原图格式和大小、回复内容、检测与最近询问时间、复用次数，以及一张最长边 512 像素的 JPEG 预览图（GIF / 动图取首帧，透明部分填白）。**不保存原图**，预览图只用于在管理面板中辨认图片，读取时不会被浏览器缓存。
- **开关**：检测缓存默认开启，可在 **检测缓存** 页顶部的「缓存设置」中关闭。关闭后每次询问都重新检测，也不再保存新结果；已保存的记录保留，仍可查看、修改或删除，重新开启后继续使用。
- **容量**：未修改的记录默认最多保留 500 条，可在「缓存设置」中改为 1–10000 条。超出时删除最久没有被询问的；修改过的记录不计入、不自动删除。调低上限后保存时立即清理多出的记录。每条记录含一张预览图，通常几十 KB。
- **删除与清空**：可在页面上逐条删除；「清空全部缓存」删除数据库中的全部缓存记录（包括修改过的记录和所有预览图），无法恢复。
- 缓存读写失败不会影响检测：读取失败时直接重新检测，保存失败时照常回复本次结果。

### 代理

代理统一在 **系统 → 网络代理** 中添加和测试（HTTP、HTTPS、SOCKS5，可添加多个），各功能分别选择使用哪一个：

| 请求 | 在哪里选择代理 |
| --- | --- |
| OpenAI C2PA / SynthID 检测 | **AI 图片检测 → 检测来源** 的「OpenAI 来源检测的代理」，随该页「保存设置」一起保存 |
| 每个视觉模型（检测、获取模型、测试、查询余额） | **AI 图片检测 → 视觉模型** 中该模型的「代理」，随「保存此模型」保存；测试等操作使用当前选择 |

选择「不使用代理」时直接连接，仍遵循进程环境中的代理变量。服务器无法直接访问 OpenAI 或 Anthropic 时，先在网络代理页添加代理并点「测试连接」确认能访问对应接口，再回到这里选择。QQ 图片下载和本地 C2PA 不经过代理。

从 v3.3.0 及更早版本升级时，原来在「X → 账号与代理」中填写的代理会自动转为名为「原 X 代理」的代理；如果原来已启用，X 与 OpenAI 来源检测会继续使用它，行为不变。

原图不在本地持久化，下载后提供给本地 C2PA 与 OpenAI 的是原始字节，以保留仍存在的凭证；只有完成检测的图片会在 [检测缓存](#检测缓存) 中保存一张缩小的预览图。本地 C2PA 检查不会自动请求图片中声明的远程凭证地址、OCSP 或信任列表。

## 如何读结果

回复从第一个已启用来源的结果开始（如本地 C2PA），依次列出各来源和视觉模型的结果，然后是结论，不附带标题或使用提示。

- **本地 C2PA 已检出**只说明存在凭证，不说明使用 AI。插件检查当前凭证及其引用的素材链中的标准 AI 生成 / 合成声明。
- **有效但来源未受信任**：签名和内容绑定校验通过，但尚不能确认签发者可信，不据此下确定结论。
- **校验失败**：元数据或内容可能被修改，不能采信其中声明。
- **OpenAI C2PA**：报告是否识别到 OpenAI AI 生成凭证及签名状态；可同时显示签发者。
- **SynthID（OpenAI）**：报告 OpenAI 接口识别到的受支持水印。它不检测所有厂商的水印。
- **视觉模型（仅供参考）**：模型根据画面推测的倾向，不是来源证据。
- 来源受信任的 AI 声明或检出的 SynthID 可以作为 AI 生成 / 编辑证据；其余情况保留不确定性。**未检出不代表非 AI**。

QQ 压缩、截图、转存、裁剪和格式转换可能删除 C2PA 或削弱水印。检测的是协议端实际提供的文件，尽量使用未压缩原图。不要从结果推断作者身份、账号或提示词。

## 文件与请求限制

- 支持 PNG、JPEG、WebP、GIF；每次一张，最多 **20 MiB、2500 万像素**。
- 多图引用会要求重新引用单张，不会静默挑选其中一张。
- 仅访问 `*.qpic.cn`、`multimedia.nt.qq.com` 和 QQNT 使用的 `multimedia.nt.qq.com.cn` 的 HTTPS 地址，不接受任意 URL、本地路径或重定向。QQNT 主机名按完整名称匹配，不放行其他相似域名。
- 每个机器人进程同时处理一条检测请求；忙时提示稍后重试。下载超时 30 秒，OpenAI 请求超时 45 秒，每个视觉模型请求超时 60 秒；外部请求不跟随重定向。
- 一次命令至多发送一次 OpenAI 请求，并向每个启用的视觉模型各发送一次请求；命中检测缓存时不发送任何检测请求。不自动重试、轮询或批量上传。
- 无法读取、地址过期、接口未配置、无权限或限流均作为失败 / 未完成状态报告。
