# 动态监控

监控 B 站 UP 主动态更新，并在指定群组/好友发送通知。

:::info 2.0 配置方式
UP 主映射在 **Web Admin → B 站 → 动态订阅** 中管理；监控间隔、截图开关等在 **B 站 → 订阅参数** 中配置，不再使用 `DYNAMIC_MONITOR_*` 环境变量。
:::

## 功能特点

- 自动监控指定 UP 主的动态更新
- 支持多 UP 主、多群/好友
- 可配置监控间隔与分散检查（见 **B 站 → 订阅参数**）
- 可选 Playwright 网页截图或莫奈动态卡片
- **置顶动态变更**时单独推送（与新动态推送不同）
- 订阅页支持 **立即检查** 手动触发一轮轮询

## 工作原理

1. 调用 B 站 Web API 获取 UP 主动态（`feed/space` 接口）
2. 记录每个 UP 主最后动态 ID，避免重复推送
3. 首次启动只记录基准点，不推送历史动态
4. 过滤直播动态（由直播监控插件负责）
5. 发现新动态时格式化推送到目标群/好友
6. 同时跟踪置顶动态 ID；置顶变更时按置顶模板推送（默认文案含「置顶了动态」）

## 投递与恢复

- 数字 QQ 群/好友通过 OneBot 投递；官方群/C2C 的 OpenID 通过官方 QQ Bot 投递，接入步骤见 [Web Admin 配置](../configuration/web-admin-setup)。
- 消息快照、待重试目标及官方消息分段进度保存到数据库；重启后继续未完成投递，不因其他目标失败重复发送给已成功的目标。已有快照的新动态即使离开最新动态列表，仍会继续投递。
- 权限、关系或内容等确定性拒绝结束本条通知的对应目标；频控、断连等临时错误保留重试。网络超时但未收到回执时无法保证严格去重。
- 官方目标的主动投递以平台权限与实际回执为准，`@全体` 使用文字提示。群消息/好友消息守卫只控制入站消息，不影响监控主动推送。

## 支持的动态类型

| B 站类型 | 说明 |
|----------|------|
| `DYNAMIC_TYPE_WORD` | 纯文字 |
| `DYNAMIC_TYPE_DRAW` | 图文 |
| `DYNAMIC_TYPE_FORWARD` | 转发 |
| `DYNAMIC_TYPE_AV` | 投稿视频 |
| `DYNAMIC_TYPE_ARTICLE` | 专栏 |
| `DYNAMIC_TYPE_MUSIC` | 音频 |

## 动态图片

在 **B 站 → 订阅参数** 开启「动态图片」，选择图片模式并保存，立即热重载：

- **网页截图（默认）**：使用 Playwright + Chromium 访问 B 站动态网页，保留页面装扮；需要安装浏览器（Docker 镜像已内置）。
- **莫奈卡片**：直接用 API 数据和 Pillow 绘制作者头像、发布时间、正文、转发文案、配图、赞/评论/转发数及链接二维码，无需访问动态网页。默认从作者头像取色，也可切换为优先从首张配图取色，无图时使用头像；所选素材不可用时使用默认紫色。Material Color Utilities 选取主题色，通过 HCT 色调板生成 tone 65 → 90 → 96 的由深到浅配色。

两种模式均应用于新动态/置顶变更推送、最新动态和置顶动态查询；不改变链接解析和图片提取。
关闭动态图片、图片生成失败或卡片配图下载不完整时，沿用文字与原图投递。已有安装默认保持网页截图。

卡片最多展示 6000 字、100 行正文与 9 张配图，多图使用方形网格，扫码或打开消息链接查看完整内容；以 API 返回内容为准，不复刻 B 站装扮、富文本表情图片和专栏完整排版。需要 Noto CJK 字体（Docker 已内置）、macOS PingFang 或 Windows 微软雅黑/黑体；新增 Python 依赖 `material-color-utilities` 与 `qrcode`，前者在 Python 3.14 环境可能需要 C++ 构建工具。

## 消息格式

```
小草Miho 发布了新投稿视频

[动态网页截图]

https://t.bilibili.com/1071700825512869927
```

文案可在 **B 站 → 消息模板** 自定义。相关模板键包括：

| 模板 | 用途 |
|------|------|
| `dynamic_template_push` | 新动态推送 |
| `dynamic_template_pinned` | **置顶动态变更**推送 |
| `dynamic_template_query_latest` / `dynamic_template_query_pinned` | 主动查询回复 |
| `dynamic_template_extract*` | `#提取` / `#获取` 图片提取 |

## 动态查询命令

在已配置 UP 主映射的群中（触发词可在 **系统 → 命令** 自定义）：

| 命令（默认） | 说明 |
|------|------|
| `最新动态` | 主动查询 UP 主最新动态 |
| `置顶动态` | 主动查询 UP 主**当前**置顶动态（查询，不是变更推送） |

## 动态图片提取命令

在群聊或私聊中发送：

- `#提取 <动态ID>`
- `#获取 <动态ID>`

可按动态 ID 拉取图片。

使用 OneBot 时，也可以引用机器人发送的动态推送或查询回复，只发送 `#提取` / `#获取`，即可提取该动态的图片，群聊和私聊均支持。仍需当前群或好友已订阅动态，命令开关、自定义触发词与前缀继续生效。

引用消息必须由当前机器人发送，并包含唯一的动态链接（`t.bilibili.com` 或 `bilibili.com/opus/`）。自定义动态消息模板应保留 `{url}`。引用原文无法获取、不含动态链接或含多个不同动态时，会提示手动填写动态 ID；命令中显式填写的 ID 或链接优先使用。

## 注意事项

- 监控间隔不建议过短，推荐 30 秒到 5 分钟
- 截图功能需要额外内存，建议容器 limit ≥ 2Gi
- 需网络可访问 B 站 API

开启「启用动态图片」后才显示图片模式，选择莫奈卡片后再显示「卡片取色来源」，可选择 **作者头像（默认）** 或 **动态配图**，保存后热重载。头像模式始终取作者头像；配图模式取第一张配图，无配图则用头像。所选取色素材不可用时使用默认紫色。关闭动态图片会保留已选模式与取色来源，已有的明确取色选择不受默认值变更影响。此设置只影响卡片配色，不改变卡片展示的头像与配图。
