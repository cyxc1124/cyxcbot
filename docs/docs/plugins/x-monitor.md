# X 推文监控

监控 X (Twitter) 博主新推文，并向配置的群/好友推送。对应插件：`x_monitor`。

:::info 配置方式
Bearer Token、代理、博主映射与检查间隔均在 **Web Admin** 中配置（侧栏 **X → 推文订阅**，以及 **X → 账号与代理 / 订阅参数**），不使用环境变量。
:::

## 功能特点

- 按 username 订阅博主，支持多目标群/好友
- 可配置检查间隔与分散检查（**X → 订阅参数**）
- 支持 HTTP / HTTPS / SOCKS5 出站代理（与链接解析共用）
- 订阅页支持 **立即检查** 手动触发一轮轮询

## 工作原理

1. 使用 X API v2 拉取用户时间线
2. 按推文 ID 游标去重，首次启动只记基准点、不推送历史
3. 发现新推文时按模板推送文字与媒体

v1 不含置顶跟踪、网页截图与群内查询命令。

## 配置

| 位置 | 说明 |
|------|------|
| **X → 推文订阅** | 博主 username 与推送映射 |
| **X → 订阅参数** | 检查间隔、分散检查 |
| **X → 账号与代理** | Bearer Token、出站代理 |
| **X → 消息模板** | `x_template_push` |

## 投递与恢复

- 数字 QQ 号走 OneBot，官方群/C2C OpenID 走官方 QQ Bot；主动能力以平台权限和实际回执为准，官方 `@全体` 使用文字提示。
- 成功目标与未完成目标的进度保存在数据库中；OneBot 按批次、官方消息按文字/图片/视频分段续传，已完成目标不会因其他目标失败重复投递。
- 重试仍需重新获取推文并下载媒体，不保存完整消息快照。模板或前缀策略改变导致发送计划变化时，未完成目标从头重发，可能补发其已经收到的部分；已完成目标保留完成标记。
- 权限、关系或内容等确定性拒绝结束对应目标；频控、断连等临时错误继续重试。未收到回执的网络超时无法保证严格去重。

## 注意事项

- 须配置有效 Bearer Token，否则无法拉取时间线
- 部分地区访问 X API / CDN 需要配置代理
- 推文媒体经代理下载后，OneBot 通过共享媒体目录读取，官方 QQ Bot 使用富媒体上传；含视频时与文案分开发送
