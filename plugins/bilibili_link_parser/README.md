# B 站链接解析

动态、直播、视频详情与播放地址查询共用 B 站多账号轮换；短链接跳转与截图使用首账号。在 Web Admin → **B 站 → 账号** 中扫码添加、验证或移除；轮换不能保证避免风控。详见 [账号配置](../../docs/docs/configuration/web-admin-setup.md#4-配置-b-站账号)。

自动识别群聊/好友中的 B 站链接并回复解析结果（视频、直播、短链、QQ 小程序分享）。

> **2.0 配置**：在 Web Admin → **群组** / **好友** 中按目标开关链接解析，可分别启用视频/直播/动态解析。
>
> 完整文档：[链接解析](https://cyxc1124.github.io/cyxcbot/docs/plugins/link-parser)

## 触发方式

无需命令，发送含 BV 号、直播间链接、`b23.tv` 短链或 B 站 QQ 小程序分享的普通消息即可。

支持 OneBot V11 与官方 QQ Bot。官方群需 @ 机器人，官方 C2C 直接发送链接；小程序/JSON/XML 分享按适配器实际收到的消息内容提取。

## 多 P 视频

单 P 视频直接解析。多 P 视频未指定分 P 时，先回复目录：

```text
《视频标题》共 3 P：

P1 开场
P2 正式内容
P3 问答

请在 5 分钟内回复 1～3 之间的数字，选择分 P。
```

原用户在同一群聊或私聊内回复 `2`，即可获取第 2 P；官方 QQ 群仍需 @ 机器人后回复数字。开启「发送视频」时下载对应分 P，关闭时只返回封面和文案，文案包含分 P 名称及对应链接。已有 `?p=2` 等参数的 BV/AV 链接直接处理对应分 P，短链、小程序分享以实际展开链接携带的分 P 参数为准。

选择按机器人、会话和用户隔离，从目录确认发送成功开始计时，5 分钟后失效。收到合法数字时立即绑定当前所选分 P 并消费待选记录，再等待会话锁和下载名额；即使第 299 秒回复、排队到第 301 秒才开始下载，也会继续处理已接收的选择。后续新目录不会替换或被这次已接收的选择消费。

同一用户在同一会话内的解析与发送按顺序处理，新视频链接替换尚未消费的待选记录，即使新视频只有一 P 或详情获取失败，旧请求也不会恢复原选择。普通数字消息在没有待选视频时不会触发解析；越界数字会提示有效范围，不延长原来的 5 分钟有效期。每次选择会重新检查当前解析权限；非法或越界的 `p` 参数不会退回第一 P。目录最多展示前 10 P，但仍可回复未展开的有效序号。

统一清理任务每 30 秒清理过期待选记录，查询和新增记录时也会清理。有效性仍严格按接收数字时的 300 秒截止时间判断，不会因为清理间隔而延长；清理与消息处理在同一事件循环中执行，插件关闭时移除清理任务并清空待选记录。

记录最多保留 512 条，满额时淘汰最早的记录，全部只保存在内存中。进程重启或崩溃会丢失待选记录和已接收但尚未完成的请求，不会恢复选择或自动补发；重启后仅回复数字不会触发解析，需要重新发送视频链接选择。视频下载或发送失败沿用现有降级行为；需再次发送同一 P 时，也重新分享链接选择即可。

官方会话首次收到消息后进入群/好友缓存。在 Web Admin 先启用该目标的「群消息」/「好友消息」，再开启 B 站解析（默认全关）。官方目标不要求连接 OneBot；缓存中的官方目标可以单独编辑，但不会把官方缓存当成完整 OneBot 列表，列表不完整时数字 QQ 目标保持只读。

官方回复使用原生图片/视频上传；官方群最多 5 次、C2C 最多 4 次，会为文案保留一条，并提示超出预算的媒体数量。下载、截图或媒体转存失败时尽量发送剩余封面/文案；权限、关系或过期拒绝停止本次发送，URL 拒绝由共享发送层去掉链接后重试。发送结束或取消后清理下载视频；取消混流会终止并等待 ffmpeg。

## 文件结构

```
plugins/bilibili_link_parser/
├── __init__.py       # 消息监听与解析调度
├── config.py         # 从 ConfigService 加载
├── message_text.py   # 消息文本提取
├── page_selection.py # 分 P 选择上下文（5 分钟）
├── miniapp.py        # QQ 小程序分享解析
├── sender.py         # 回复消息构建
└── README.md
```
