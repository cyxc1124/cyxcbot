# AI 图片检测

OneBot V11 群聊或私聊中，引用一条只包含一张图片的消息，发送触发词（默认 `ai吗？`、`ai吗?`、`ai吗`）。触发词在 Web Admin → **AI 图片检测 → 触发命令** 中修改或关闭，匹配不区分英文大小写；与其他命令一样支持裸触发词、命令前缀和 `@机器人`，保存时做冲突检查。沿用群聊 / 私聊消息守卫。

机器人会引用原始图片消息返回检测结果；检测失败或繁忙提示也引用同一条原消息。未引用消息时，操作提示引用用户发送的命令消息。

## 检测来源（AI 图片检测 → 检测来源）

三项可分别开关，关闭的来源不执行、不出现在回复中；全部来源和视觉模型都关闭时只提示管理员未启用检测。

- **本地 C2PA**：通过 c2pa-python 读取嵌入式 C2PA，并校验签名和图片绑定；区分凭证存在、AI 声明、来源信任和校验失败。
- **OpenAI C2PA**、**SynthID（OpenAI）**：保存 OpenAI API Key 后，原图上传固定的官方 Content Provenance API。该接口一次返回两项结果、不支持只查其中一项，因此任一开启就上传一次原图，两项都关闭时不调用 OpenAI。密钥加密保存，不在设置响应或日志中返回。
- OpenAI 请求使用「AI 图片检测 → 检测来源」中为它选择的代理（代理统一在 Web Admin → 系统 → 网络代理维护），保存后立即生效；选择不使用代理时直接连接，仍遵循运行环境的代理变量。QQ 图片下载与本地 C2PA 不经过代理。
- 开启 OpenAI 但未配置密钥时，回复明确标注未完成检测；外部调用失败也保留其他结果，不把错误当作未检出。
- OpenAI 接口仅验证其支持的 OpenAI 来源信号，不是通用 AI 图片分类器。没有信号时回复“无法判断”，不判定为真人创作。

## 视觉模型共同识别（AI 图片检测 → 视觉模型）

- 供应商数量不设上限，接口类型为 **OpenAI 兼容**（`{地址}/chat/completions`，默认 `https://api.openai.com/v1`）或 **Anthropic**（`{地址}/v1/messages`，默认 `https://api.anthropic.com`）。可填写兼容服务的地址；无需鉴权的本地服务可不填密钥。每次检测会向每个已启用的模型各发一次带图请求，费用与回复长度随启用数量增长。
- 每个供应商可单独启用，并单独选择一个代理或直接连接。API Key 逐条加密保存、只写不读；修改接口类型或地址时须重新填写，避免已存密钥被发往新地址。
- Web Admin 列表默认收起，每个供应商单独保存（`POST/PATCH/DELETE /api/v1/ai-image/vision/providers`），启停开关立即生效。配置仍是 SystemSetting 中的一条 JSON，读改写由 `ConfigService` 内的锁串行化，同时保存不同供应商不会互相覆盖。
- 启用的模型与 OpenAI 检测并行请求，各自返回「倾向 AI 生成 / 倾向非 AI 生成 / 无法判断」、置信度和简短理由；回复汇总多数意见。视觉模型只作参考：受信任的来源证据始终优先，多数倾向非 AI 也不能证明非 AI。
- Web Admin 可按未保存的表单值获取模型列表（标注接口声明的图片输入能力）、用生成的测试图测试响应（耗时、判断与 token 用量），并查询 DeepSeek 与 Kimi 官方接口的余额。这些请求由 `admin/api/v1/ai_image.py` 发起，上游错误说明只在管理面板显示。
- 发送前不重新编码 PNG / JPEG / WebP 小图；GIF、动图及超过 2048 像素或约 3.5 MB 的图片转为不超过 2048 像素的首帧 JPEG。单个模型请求超时 60 秒，失败只影响该模型的结果；不展示上游错误详情。

## 检测缓存（AI 图片检测 → 检测缓存）

- 完整的检测结果按图片原始字节的 SHA-256 存入表 `shared_db_aiimagecache`（`cache.py`）。同一图片再次询问时直接回复保存的结果并注明来自此前检测，不再请求 OpenAI 或视觉模型；有来源或模型失败时不保存。
- 每条记录带检测配置指纹（`shared/config/ai_image.py` 的 `detection_fingerprint()`：来源开关、是否配置 OpenAI 密钥、启用的视觉模型、回复格式版本）。配置变化后，未修改的结果下次询问时重新检测并覆盖。
- Web Admin 列表查看预览图、回复与哈希，可修改或删除（`admin/api/v1/ai_image_cache.py`）。修改过的结果始终沿用、不被覆盖或自动清理，回复注明为管理员复核后的结果。
- 只保存最长边 512 像素的 JPEG 预览图，不保存原图；未修改的记录最多 500 条，超出时删除最久没被询问的。缓存读写失败不影响检测。

## 限制

- 支持 PNG / JPEG / WebP / GIF，单图最多 20 MiB、2500 万像素。仅下载 QQ 图片 CDN，包括 NapCat 等协议端使用的 `multimedia.nt.qq.com.cn`；禁止跳转和本地文件路径，不保存原图（检测缓存只保存缩小的预览图）。
- 一个进程同时处理一条检测请求；繁忙时直接提示重试。外部请求不自动重试，不进行批量识别。
- 官方 QQ Bot 的引用图片未接入；本次只支持现有 OneBot 引用消息机制。

入口在 `__init__.py`；下载、C2PA、OpenAI 接口、回复和检测缓存分别位于同目录模块。视觉模型的 HTTP 封装（判断、模型列表、余额、图片预处理）在 `utils/vision_api/`，供插件和 Web Admin 共用；供应商配置解析在 `shared/config/ai_image.py`。配置复用 SystemSetting；检测缓存使用独立的 `shared_db_aiimagecache` 表，启动时由迁移自动创建。

完整使用说明、限制与其他服务价格调研见 [文档站页面](../../docs/docs/plugins/ai-image-detector.md)。
